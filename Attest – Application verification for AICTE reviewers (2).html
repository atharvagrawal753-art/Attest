    What PS SIH26261 asks for

    Organisation: AICTE · Category: Software. Attest answers the three parts of the problem statement.

    Application validation

    Checks that an application is complete and that its details agree across documents.

    Document authentication

    Flags possible alterations and inconsistent metadata for a person to examine, without claiming proof of fraud.

    Regulatory compliance verification

    Applies a configurable rule set and shows the evidence behind each result.

    From upload to report in five steps

    Each step is visible to the reviewer, so nothing is a black box.

    1

    Upload

    PDFs and scanned certificates.

    Accepts PDF, JPG and PNG. Each file is stored with a hash so later edits are detectable.
    2

    Extract

    OCR reads names, dates, numbers.

    PyMuPDF for digital PDFs, PaddleOCR for scans. Every value keeps its page and position.
    3

    Compare

    Fields are matched across documents.

    Names and numbers are normalised, then compared. Disagreements show both values side by side.
    4

    Check rules

    A configurable rule set is applied.

    Rules are plain configuration, so reviewers can change a threshold without touching code.
    5

    Report

    Findings come with their evidence.

    Passed checks, warnings, evidence and a suggested next action, ready for the reviewer.

    Cross-document matching

    Shows exactly which fields disagree and where each value was found.

    Authenticity signals

    Flags possible alterations or odd metadata. These are warnings for a person to examine, not proof of fraud.

    Explainable rules

    Every warning names the rule, the evidence found, and what the reviewer should verify.

    The reviewer decides

    Attest recommends. An authorised reviewer approves, rejects, or asks for corrections, and every decision is recorded with a reason.
